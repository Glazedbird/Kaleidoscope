# ADR-0002：以统一 token 契约组织递归下降与优先级解析

- 状态：已实现，依据现有代码补记。
- 记录日期：2026-11-07，不代表最初决策日期。
- 证据：[Parser.h](../../Parser.h)、[Parser.cpp](../../Parser.cpp)、[main.cpp](../../main.cpp)、[tests/parser_test.cpp](../../tests/parser_test.cpp)；主要实现见 `ff1210d`。

## 背景

数字、变量、括号、函数调用都需要递归组合；二元运算还必须处理优先级与结合性。如果每个解析函数对 token 推进的理解不同，嵌套调用可能丢失分隔符，调用方也难以继续解析下一条语句。

开发中曾存在未完成的 `ParseBinOpRHS()` 草稿，只读取运算符和右侧，尚未完成右侧优先级递归与二元节点构造。声明顺序和程序入口混放也增加了联调问题。

## 决策

1. `CurTok` 表示尚未消费的 token；先由驱动调用 `getNextToken()` 初始化，解析函数通过该函数推进输入。
2. 成功返回 AST，并停在该结构之后的第一个 token；失败输出诊断、返回 `nullptr`。错误恢复由主循环统一负责。
3. `ParsePrimary()` 分派数字、标识符和括号。标识符根据后续是否出现 `(` 区分变量引用与函数调用。
4. `ParseExpression()` 读取左侧 primary，再交给 `ParseBinOpRHS()`。优先级为 `<:10`、`+:20`、`-:20`、`*:40`。
5. 右侧遇到更高优先级时，先递归形成右子树；同级在循环中依次合并，保持左结合。未列入优先级表的 token 结束当前表达式。
6. `RecoverFromError()` 将输入推进到分号、下一条 `def` / `extern` 或 EOF。主循环消费分号，且保留“曾发生错误”的状态决定最终退出码。

## 理由与代价

递归下降使各语法规则与对应函数直接关联；优先级解析集中处理二元运算，无需为每个优先级复制一套语法函数。明确 token 的停留位置，使括号、调用、函数体和顶层语句能够组合。

错误恢复可以在一条坏语句后继续处理后续声明，同时以退出码 `1` 告知调用方输入并非全部成功。它是按同步 token 跳过输入的策略，不保证保留错误语句内的其余内容。

当前优先级表固定，函数原型与调用参数遵循不同分隔规则；新增语法需要同时更新解析、示例和测试。此决策不包含语义检查或表达式执行。

## 验证

`tests/parser_test.cpp` 验证 `1 + 2 * 3`、`(1 + 2) * 3`、`10 - 3 - 2` 等的 AST 形状，并检查解析结束后仍停在语句分号上。`tests/cli_test.py` 检查错误恢复、EOF、诊断和退出状态；子进程设置超时以发现卡死。

2026-11-07 复盘时执行 `make -B test`，11 条语句的 AST 校验和 7 个 CLI 测试方法通过。该结果不覆盖伪终端交互或非法数字的完整规则。
