# ADR-0001：分离前端模块，并以独占所有权组织 AST

- 状态：已实现，依据现有代码补记。
- 记录日期：2026-11-07，不代表最初决策日期。
- 证据：[token.h](../../token.h)、[ExprAST.h](../../ExprAST.h)、[ExprAST.cpp](../../ExprAST.cpp)、[Parser.h](../../Parser.h)、[Makefile](../../Makefile)；Git 基线 `ff1210d`。

## 背景

早期 Lexer 与测试入口放在一个文件内，`gettok()` 和词法结果使用文件级 `static`。AST 类和解析代码也曾混在一起。单文件组织可以局部阅读，但后续 Parser 无法通过正式接口访问 Lexer 或 AST；仅新增解析代码不能解决跨翻译单元的可见性与链接问题。

AST 同时需要明确子树由谁持有，特别是调用实参和函数体可能包含任意表达式结构。

## 决策

1. `token.h` 声明 token 枚举、`gettok()` 和词法结果；`token.cpp` 提供单一定义。共享变量以 `extern` 声明，Lexer 保留内部的静态读取位置。
2. `ExprAST.h` 保存类型定义，`ExprAST.cpp` 实现构造函数。Parser 包含头文件，构建系统编译和链接实现文件。
3. `Parser.h` 暴露顶层解析接口，`Parser.cpp` 实现解析；辅助函数具有实现文件内的可见性。`main.cpp` 负责生产程序入口与驱动。
4. AST 通过 `unique_ptr` 拥有子树，构造时用 `std::move` 转交所有权；表达式基类提供虚析构函数。
5. 函数原型与函数体通过 `FunctionAST` 组合。调用节点仅保存函数名与实参树，原型、定义和调用保持各自职责。

## 理由与代价

模块拆分使 Lexer、Parser、AST 和测试驱动可以分别编译，公共接口可被主程序和独立测试复用。独占所有权与树的父子关系相符，节点释放会递归释放拥有的子树，不需要手工管理每个子节点的生命周期。

当前仍使用全局词法结果、全局 `CurTok` 和静态输入位置，接口简单，但没有解决可重入、多实例或并发解析。共享子表达式图或持久函数表也不是本次设计的一部分。

## 验证与历史修复

早期拆分后曾通过跨文件数字解析验证。随后 AST 改名时，头文件和实现的 `Ast` / `AST` 拼写未同步，完整构建失败；`ff1210d` 已统一为 `VariableExprAST` 与 `BinaryExprAST`。

2026-11-07 复盘时运行 `make -B test`，所有生产模块与测试重新编译、链接成功。该结果证明当前主构建可用，不包含未纳入 Makefile 的 `toy.cpp`。
