# Kaleidoscope 工程知识整理

本文提炼前端开发中可复用的知识。当前结构见[架构说明](architecture.md)，问题发生与修复过程见[开发复盘](development-log/2026-11-07-frontend-review.md)。

## 1. 跳过注释后，要继续返回有效 token

[token.cpp](../token.cpp) 的 `gettok()` 在遇到 `#` 时，读取至换行、回车或 EOF。

- 停在换行处：调用 `return gettok()`，由函数开头跳过空白并继续寻找下一个 token。
- 停在 EOF：不再递归，进入后面的 `tok_eof` 返回分支。

`LastChar` 是静态变量，递归调用会保留上一次读取位置。这里的递归服务于“整条注释不产生 token”，不是语法分析递归。

## 2. 跨文件调用需要同时满足声明可见与链接可见

头文件解决调用方“知道接口”的问题；源文件中的定义和链接步骤解决“找到实现”的问题。

当前 [token.h](../token.h) 声明 `gettok()`，并用 `extern` 声明词法结果；[token.cpp](../token.cpp) 提供实际定义。命名空间作用域的 `static` 会限制名字在当前翻译单元内使用，因此公共 Lexer 接口不能保留原来单文件版本的文件级 `static`。

函数内的 `static int LastChar` 则用于保持读取状态，与公共接口的链接可见性是不同问题。不要为了开放 `gettok()`，连带移除这个状态变量。

工程约定：通过头文件引用接口，由 Makefile 链接实现文件；生产程序入口位于 `main.cpp`，测试可拥有自己的独立入口。内部解析辅助函数留在 `Parser.cpp` 的匿名命名空间。见 [ADR-0001](decisions/0001-frontend-modules-and-ownership.md)。

## 3. 函数声明、定义、调用保存不同的信息

| 语法 | 节点 | 关键区别 |
| --- | --- | --- |
| `extern add(x y)` | `PrototypeAST` | 只有函数接口，没有函数体 |
| `def add(x y) x + y` | `FunctionAST` | 组合函数原型与函数体 |
| `add(1, 2)` | `CallExprAST` | 描述一次调用，保存实参表达式，不复制函数定义 |

原型的参数是 `vector<string>`，调用的参数是 `vector<unique_ptr<ExprAST>>`。因为实参可以是数字、变量、运算或嵌套调用，不能仅保存数值或形参名。

当前 Parser 只构建这些结构，不根据函数名做存在性或实参数量检查。

## 4. `unique_ptr` 表达父节点拥有子树

[ExprAST.cpp](../ExprAST.cpp) 中的 `m_args(std::move(args))` 将参数树的所有权转交给调用节点。包含 `unique_ptr` 的 `vector` 不能复制；二元节点的左右子树、函数的原型和函数体也通过移动转交。

移动所有权与返回局部结果要区分：返回局部 `unique_ptr` 时可以直接 `return Result;`，不需要到处显式写 `std::move`。父节点释放时，拥有的子树随之释放。

## 5. 解析正确性包括 token 停留位置与 AST 形状

解析 `1 + 2 * 3;` 后，树应是 `(+ 1 (* 2 3))`，并且 `CurTok` 仍为 `';'`。仅输出“解析成功”不足以证明优先级正确，也不能证明调用方没有多消费 token。

[tests/parser_test.cpp](../tests/parser_test.cpp) 的 `Describe()` 检查树形，`NextStatement()` 检查分号边界。新增运算符或调整解析流程时，应同时验证优先级、结合性、括号覆盖规则及 token 边界。见 [ADR-0002](decisions/0002-parser-contract-and-precedence.md)。

## 6. 分模块验证与完整构建具有不同的证明范围

当 AST 的类名不一致导致完整构建失败时，曾单独编译 `main.cpp + token.cpp` 验证 Lexer。这能隔离词法模块，不能据此声称 Parser 或整个项目已经可用。

当前主程序已加入 Parser，复现独立词法调试应使用 `./build/kaleidoscope --tokens`。历史阶段的独立编译命令不应直接作为当前构建命令。

## 建议补充的自动化测试

以下是建议，尚未在本次文档维护中实现。

| 优先项 | 建议位置与方法 | 验收内容 |
| --- | --- | --- |
| 注释终止边界 | 扩展 `tests/cli_test.py` 的 `--tokens` 子用例，覆盖 LF、CRLF、无末尾换行和 EOF | 注释不产出 token，后续 token 不丢失，EOF 正确返回且不挂起 |
| 非法数字 | 先明确合法数字规则，再为 `.`、`1.2.3` 等添加回归用例 | 定义诊断、退出状态和恢复行为后，再实现断言 |
| 真实交互模式 | 使用伪终端启动主程序，并设置超时 | 提示符可见、分号后继续读取、EOF 可以退出 |
| 多输入状态隔离 | 仅在引入 Lexer 实例或重置接口时增加 | 不把上一个输入的 `LastChar`、词法结果或 `CurTok` 带入下一个输入 |

非法数字目前属于需进一步验证的问题：`gettok()` 允许连续读取数字和小数点，且没有检查 `strtod` 的转换终点。该结论来自代码检查，本次没有运行这些输入，不能将其具体输出或诊断写成已测结果。

语法修改时同步更新[示例](../examples/demo.k)、AST 结构测试和 CLI 测试；汇报中区分“类型已定义”“解析草稿已写”和“整体构建及测试通过”。
